# Rule catalogue

Generated by `scripts/gen_rules_doc.py`. Rules with level *informational* are building blocks: they never alert on their own, correlation rules build on them.

## ssh

| Rule | Level | Type | ATT&CK / tactic | What it detects | Known false positives |
|---|---|---|---|---|---|
| `ssh_compromise` | critical | temporal_ordered | credential access, T1110, initial access, T1078 | A successful SSH login from an address that just triggered the brute-force detection. Treat the account as compromised until proven otherwise. | A legitimate user behind the same NAT address as an attacker. |
| `ssh_bruteforce` | high | event_count | credential access, T1110.001 | Many failed SSH logins from one source address in a short time. | Misconfigured automation or a user with a stale saved password retrying in a loop. |
| `ssh_password_spray` | high | value_count | credential access, T1110.003 | One source address fails to log in as many different accounts (spraying or user enumeration). | Vulnerability scanners run by your own team. |
| `ssh_root_login` | medium | rule | initial access, T1078 | Direct SSH login as root. Most hardening guides recommend disabling this. | Legacy administration workflows. |
| `ssh_slow_bruteforce` | medium | event_count | credential access, T1110.001 | Low-and-slow guessing that stays under the fast brute-force threshold but adds up over an hour. | Shared NAT address in front of many users who occasionally mistype their password. |
| `ssh_accepted_login` | informational | rule | - | Building block. A successful SSH login. | - |
| `ssh_failed_login` | informational | rule | - | Building block. A failed SSH password/key/keyboard-interactive login. | - |
